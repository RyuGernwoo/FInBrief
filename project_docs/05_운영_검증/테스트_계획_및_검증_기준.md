# TEST_PLAN - FinBrief

## 1. Test Strategy

FinBrief의 테스트는 7일 MVP에서 발표 가능한 end-to-end 증거를 만드는 데 집중한다. 핵심은 "구독 설정 -> 지표/뉴스 수집 -> 리포트/카드 생성 -> 캐시 -> 발송 -> 관측/평가" 흐름이 실제로 한 번 완주되는지다.

## 5. Automatic Evaluation

평가 파일은 `evals/finbrief_eval_set.jsonl`로 둔다.

평가 항목:

- 수치 방향 일치
- 토픽 유형 분류 정확도
- 뉴스 근거 포함 여부
- disclaimer 포함 여부
- 투자 조언 금지 준수
- 카드 섹션 형식 준수
- 한국어 브리핑 톤 준수

LLM-as-a-Judge는 보조 평가로만 사용하고, 수치 계산과 금지어 검사는 deterministic rule로 먼저 검증한다.

## 6. Manual Demo Script

1. `GET /api/v1/health`
2. `POST /api/v1/subscriptions/u_001/topics`로 `반도체` 추가
3. `GET /api/v1/subscriptions/u_001`로 목록 확인
4. `POST /api/v1/reports/run`으로 배치 수동 실행
5. 전체 지표 리포트 URL 확인
6. `GET /api/v1/cards/today?user_id=u_001`로 카드 확인
7. Discord/Slack 메시지와 delivery log 확인
8. Langfuse trace 또는 로컬 trace artifact 확인
   - `LANGFUSE_ENABLED=false`: `trace_id`가 `local_mock_trace_*`로 반환된다.
   - `LANGFUSE_ENABLED=true`: Langfuse UI에서 `finbrief.report.run` 또는 `run_id`로 trace를 검색한다.
   - trace metadata에 `run_id`, `run_date`, `topic_id`, RAG evidence count, delivery count가 남는지 확인한다.
9. `/reports/run` 응답의 `eval_summary`와 `eval_runs` 저장 결과에서 safety 위반 0건 확인
